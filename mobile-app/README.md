# Patient mobile app

The patient app of the Secure Health Monitoring IoMT system: live vitals with a
context-aware health status, a full-screen emergency alert with a countdown, the
heart-rate history with the alert timeline, and the paired watch with privacy
choices. Built with Expo (React Native, TypeScript strict). Target platform:
Android only (D34). The same code runs in a desktop browser so the UI can be
reviewed before the Android build exists.

Slice M1 (this folder) covers the four screens and the login against the real
backend, with polling instead of push. Later slices add FCM push (M2) and BLE,
with the phone acting as the outdoor gateway (D32), through an Expo
development build.

## Run in a browser

Start the backend first on its default `http://localhost:8080`, with
`CORS_ORIGIN=http://localhost:5173,http://localhost:19006` so the web app and this
preview can both call it (see `cloud/backend/README.md`). If the backend runs on
another port, set `EXPO_PUBLIC_API_URL`, e.g. `EXPO_PUBLIC_API_URL=http://localhost:8081 npm run web`. Then:

```bash
cd mobile-app
npm install
npm run web          # expo start --web --port 19006
```

Open <http://localhost:19006>. On a wide screen the app sits in a phone-width
column (max 430 px); use the browser's device toolbar at 390 × 844 for the
intended size. Dev accounts (password `iomt-dev-password`): `bn017@iomt.local`
(device streaming), `bn031`, `bn009` (with devices), `bn021`, `bn004`, `bn025`
(no device). The backend allows 5 login attempts per 5 minutes per IP.

## Run on Android (later)

The app uses only libraries with Android support (expo-secure-store,
react-native-svg, Expo Router). For Expo Go or a development build:

```bash
EXPO_PUBLIC_API_URL=http://10.0.2.2:8080 npm run android   # Android emulator
EXPO_PUBLIC_API_URL=http://<LAN IP of the backend>:8080 npm start   # phone on the same Wi-Fi
```

`10.0.2.2` is the emulator's alias for the host machine. A phone needs the
backend reachable on the LAN and, for anything other than local testing,
HTTPS. BLE and FCM need a development build (`npx expo run:android` or
`eas build --profile development`); the `android/` folder is generated by
`npx expo prebuild` and is not committed.

## Layout

```
src/
  app/                 Expo Router routes (file = screen)
    _layout.tsx        providers, fonts, session restore, auth guard (Stack.Protected)
    login.tsx
    (tabs)/            Trang chủ · Cảnh báo · Lịch sử · Thiết bị, custom text tab bar
    emergency/[alertId].tsx   full-screen alert
  api/                 generated schema, type aliases, fetch client with refresh-on-401
  features/
    auth/              JWT decode, token store, session (single-flight refresh), login screens
    home/              status helper, live vitals queries, home screen and tiles
    alerts/            alert wording, emergency watcher, alert list and emergency screen
    history/           ranges, rollup query, SVG heart-rate chart, history screen
    devices/           consent mapping, device and privacy screen
  components/          shared UI (tiles, captions, notice banner, tab bar, phone frame)
  state/               query client, session and patient hooks
  i18n/vi.ts           every Vietnamese string the patient sees
  theme/               colour tokens and fonts of the report wireframe
  utils/               time and number formatting
__tests__/             Jest tests
```

Rules: English code and comments, TSDoc on every export, no `any`, Error
subclasses only, and no text inside JSX (ESLint `no-restricted-syntax`; put it
in `src/i18n/vi.ts`). Patient wording avoids technical words such as "model",
"firmware", "gateway" or "buffer". Only generated OpenAPI types are used; there
are no hand-written DTOs.

## Behaviour notes

- Tokens: login returns a token pair; the access token is refreshed one minute
  before it expires, with one shared request at a time (a reused refresh token
  revokes the session). A refused refresh returns to the login screen. Tokens
  are kept with expo-secure-store on Android and in memory plus
  `sessionStorage` in a browser.
- Polling: latest reading, last 60 s of raw readings and alerts every 10 s;
  steps today every 60 s. The watch counts as connected while the latest
  reading is less than 2 minutes old.
- Emergency screen: opens on its own when a poll finds a new open critical
  alert, or from the Cảnh báo tab. "Tôi ổn" acknowledges the alert; "Cần giúp
  ngay" and the end of the 25 s countdown only close the screen with a
  confirmation, because the backend escalates unacknowledged alerts itself.
- Privacy toggles append consent records (`monitoring`, `model_training`,
  form version 1.0); the state shown is the newest record per scope.
- Non-patient accounts see a message that the app is for patients, with a
  logout button.
