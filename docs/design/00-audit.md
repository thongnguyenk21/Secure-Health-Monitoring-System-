# 00 — Architecture & Documentation Audit (Read-Only)

**Repo:** `.`
**Scope:** the entire directory tree, every existing file (18 files, 30 empty directories), benchmarked against a production-grade monorepo standard for a 3-tier IoMT system (IoT / Edge / Cloud / Mobile).


## 0.0 Final technology decisions (FINAL stack — binding for `01`–`04`)

Every finding below is evaluated against the agreed stack. The remediation approaches in `01`–`04` use **only** this stack; Java/Spring/Maven/Flyway are removed entirely. MVP/LATER **phase tags are fixed by ADR-0020 (`01 §0`)**, not by this stack table — a tier listed here is not automatically MVP.

| Tier | Language / runtime | Main libraries |
|---|---|---|
| IoT firmware (`iot-node`) | **Rust** (nested Cargo workspace), `no_std` where possible | `esp-hal` / `esp-idf-svc`; SNN LIF written in Rust |
| Edge-lite (`edge-gateway/edge-lite/services`) — runs ON **Pi 3B+** (aarch64, budget ≤ ~400 MB) | **Rust** (`tokio`) | `btleplug`, `tonic`+`prost` (gRPC), `axum` (REST; **no MQTT client in the MVP — D14**), `tract`/`ort` (ONNX int8), `rusqlite`/`sled` (SQLite — **NOT Postgres**) |
| Edge-train (`edge-gateway/edge-train/ml`, `edge-gateway/edge-train/services/local-trainer`) — powerful machine, **does NOT run on Pi** | **Python** (uv/pyproject) | PyTorch, Transformers, SSL, Flower client |
| Cloud backend (`cloud/backend`) | **Rust** | `axum` + `sqlx` + `sqlx migrate` on PostgreSQL/TimescaleDB |
| Cloud FL server (`cloud/fl-server`) | **Python** | Flower |
| Mobile (`mobile-app`) | **TypeScript** | React Native |
| Research/measurement (`experiments`, `benchmarks`) | **Python** (uv) | PyTorch, Flower, benchmark harness |
| Cross-language contracts (`shared/protocols`) | Protobuf + OpenAPI (+ JSON Schema/AsyncAPI) | codegen → **Rust (prost/tonic), TypeScript, Python**; plus a shared Rust crate for domain types |
| Infrastructure | Docker Engine + Docker Compose (`deploy/compose/compose.pi3.yml`) **on the Pi** as the primary edge deployment (**D13: no K3s on the Pi in the MVP**; K3s server on the dev machine only to validate `deploy/k8s`/`deploy/helm`; K3s agent on the Pi `[LATER]`), **no MQTT in the MVP** (D14/D17: IoT→Edge = BLE GATT; Edge→Cloud = gRPC/HTTPS; MQTT `[LATER]`), Prometheus/Grafana (run **outside** Pi) — **ONE single deploy home** at root `deploy/` | GitHub Actions CI splits jobs by language: `cargo fmt/clippy/test`, `ruff/pytest`, `eslint/tsc`; **multi-arch `docker buildx build --platform linux/amd64,linux/arm64`** + cross `aarch64-unknown-linux-gnu` |

Impact on the audit: S0/S1 findings remain fully valid; findings with a Java/Maven origin are updated with Rust remediation approaches. Three new findings **F-031..F-033** reflect the Pi 3B+ 1 GB runtime constraint, duplicate deploy homes, and a governance/tooling scope too broad for the MVP.

## 0. Baseline evidence (measured reality)

- `git status` → `fatal: not a git repository` → the repo **has not been `git init`-ed**. Every Git mechanism (CI, CODEOWNERS, branch protection, tags, OTA versioning) currently **cannot work**.
- `find . -type d -empty` = **30 empty directories** (see `02-migration-plan.md` for how to handle them).
- `.github/workflows/` is **empty** → no CI/CD despite the many mentions in README/Jd/WP.
- Missing `LICENSE`, `CODEOWNERS`, `CONTRIBUTING.md`, `SECURITY.md`, `CHANGELOG.md`, `docs/adr/**`, content in `shared/protocols/**`, `Cargo.toml`/`rust-toolchain.toml`/`deny.toml`, `.env.example`, `.editorconfig`, `.gitattributes`, `.dockerignore`.

## 3. Conclusion

The repo is currently an **outline + empty scaffolding**, not yet a production-grade monorepo. Four root problems must be addressed before anything else:

1. **No machine-readable source of truth** (contracts) and **no source/build** → F-002, F-009.
2. **Docs are self-contradictory and misdescribe the directory tree** → F-003, F-004, F-007, F-015.
3. **Missing operational foundations** (Git, CI, secrets, observability, governance) → F-001, F-010, F-017, F-018, F-019.
4. **Not yet anchored to the real runtime constraint (Pi 3B+ 1 GB)** and still has two deploy homes + an over-broad governance scope → F-031, F-032, F-033.

The target design, migration plan, spec standard, and task breakdown are in `01`–`04` respectively.
